# 服务器数据库初始化迁移手册

## 目的

将本地 Docker PostgreSQL 中已经准备好的初始数据，完整导入服务器 PostgreSQL，用于初始化服务器数据库。

这次迁移的前提是：

- 本地数据库是初始化基线
- 服务器目标库允许被本地数据覆盖
- 服务器代码版本与本地导出时保持一致

## 项目背景

当前仓库使用：

- Docker Compose 管理服务
- PostgreSQL 作为主数据库
- FastAPI + Tortoise ORM
- Aerich 管理数据库迁移

相关文件：

- `compose.yaml`
- `app/settings/config.py`
- `app/core/init_app.py`
- `.env.docker`

## 推荐方案

采用数据库级整库导出和导入，不走接口同步，不写逐表脚本。

原因：

- PostgreSQL 到 PostgreSQL 是同构迁移
- 不会漏掉中间表、索引、序列、自增值
- 适合 1 万到 50 万规模数据
- 当前目标是初始化服务器数据库，不是双向同步

## 执行顺序

1. 本地确认初始数据完整
2. 服务器部署与本地一致的代码
3. 服务器备份当前数据库
4. 停掉写库服务
5. 本地导出整库
6. 将 dump 文件传到服务器
7. 清空服务器目标库
8. 导入本地初始数据
9. 启动服务
10. 校验数据和功能

## 一、迁移前检查

确认本地和服务器数据库配置：

- `POSTGRES_HOST`
- `POSTGRES_PORT`
- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `POSTGRES_DB`

本地可参考：

- `compose.yaml`
- `app/settings/config.py`

服务器可参考：

- `.env.docker`

## 二、本地导出

在项目根目录执行：

```bash
docker compose exec -T postgres pg_dump -U sym -d sym -Fc > init-data.dump
```

如果用户名或数据库名不是 `sym`，替换成实际值。

导出完成后检查文件：

```bash
ls -lh init-data.dump
```

## 三、传输到服务器

```bash
scp init-data.dump <server_user>@<server_ip>:/tmp/init-data.dump
```

示例：

```bash
scp init-data.dump root@115.227.18.130:/tmp/init-data.dump
```

## 四、服务器备份当前数据库

即使你认为服务器是空库，也建议先备份。

如果服务器 PostgreSQL 可直接连接：

```bash
pg_dump -h 127.0.0.1 -p 5432 -U sym -d sym -Fc -f /tmp/server-backup-before-init.dump
```

如果服务器数据库也跑在当前项目的 Docker Compose 中：

```bash
docker compose --env-file .env.docker exec -T postgres pg_dump -U sym -d sym -Fc > /tmp/server-backup-before-init.dump
```

## 五、停掉写库服务

在服务器项目根目录执行：

```bash
docker compose --env-file .env.docker stop api worker beat
```

通常不需要停 `nginx`。

## 六、清空服务器目标库

推荐直接重建 `public schema`：

如果 PostgreSQL 可直接连接：

```bash
psql -h 127.0.0.1 -p 5432 -U sym -d sym -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
```

如果 PostgreSQL 在 Docker 容器中：

```bash
docker compose --env-file .env.docker exec -T postgres psql -U sym -d sym -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
```

## 七、导入本地初始数据

如果 PostgreSQL 可直接连接：

```bash
pg_restore -h 127.0.0.1 -p 5432 -U sym -d sym --no-owner --no-privileges /tmp/init-data.dump
```

如果 PostgreSQL 在 Docker 容器中：

```bash
cat /tmp/init-data.dump | docker compose --env-file .env.docker exec -T postgres pg_restore -U sym -d sym --no-owner --no-privileges
```

## 八、启动服务

```bash
docker compose --env-file .env.docker up -d
```

## 九、校验

先检查服务状态：

```bash
docker compose --env-file .env.docker ps
```

再校验关键表数据量。

如果服务器宿主机已经安装了 PostgreSQL 客户端，可直接执行：

```bash
psql -h 127.0.0.1 -p 5432 -U sym -d sym -c 'SELECT COUNT(*) FROM "user";'
psql -h 127.0.0.1 -p 5432 -U sym -d sym -c 'SELECT COUNT(*) FROM category;'
psql -h 127.0.0.1 -p 5432 -U sym -d sym -c 'SELECT COUNT(*) FROM brand;'
psql -h 127.0.0.1 -p 5432 -U sym -d sym -c 'SELECT COUNT(*) FROM home_layout;'
psql -h 127.0.0.1 -p 5432 -U sym -d sym -c 'SELECT COUNT(*) FROM product_import_task;'
```

如果宿主机没有安装 `psql`，推荐直接在 Docker 容器内执行：

```bash
docker compose --env-file .env.docker exec -T postgres psql -U sym -d sym -c '\dt'
docker compose --env-file .env.docker exec -T postgres psql -U sym -d sym -c 'SELECT COUNT(*) FROM "user";'
docker compose --env-file .env.docker exec -T postgres psql -U sym -d sym -c 'SELECT COUNT(*) FROM category;'
docker compose --env-file .env.docker exec -T postgres psql -U sym -d sym -c 'SELECT COUNT(*) FROM brand;'
docker compose --env-file .env.docker exec -T postgres psql -U sym -d sym -c 'SELECT COUNT(*) FROM home_layout;'
docker compose --env-file .env.docker exec -T postgres psql -U sym -d sym -c 'SELECT COUNT(*) FROM product_import_task;'
```

建议优先执行 `\dt` 确认表已经导入成功，再执行各表的 `COUNT(*)`。

再做业务验收：

- 管理后台能否登录
- 首页配置是否正常显示
- 分类、品牌、联系人等数据是否存在
- 图片和资源链接是否可访问

## 十、回滚

如果导入后出现问题，可恢复服务器原备份：

```bash
psql -h 127.0.0.1 -p 5432 -U sym -d sym -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
pg_restore -h 127.0.0.1 -p 5432 -U sym -d sym --no-owner --no-privileges /tmp/server-backup-before-init.dump
docker compose --env-file .env.docker up -d
```

## 十一、注意事项

### 1. 代码版本必须一致

项目启动时会自动执行迁移。如果服务器代码版本和本地导出时不一致，可能导致导入后再次迁移，造成结构或数据异常。

### 2. 这是覆盖式初始化

这套方案默认本地数据库是初始化基线，服务器目标库会被覆盖，不适合保留服务器现有业务数据的场景。

### 3. 可能还需要同步文件

当前项目除了数据库，还有以下 volume：

- `postgres_data`
- `redis_data`
- `uploads_data`
- `tmp_data`

如果你的初始化数据依赖本地上传文件，而不是 R2、七牛等对象存储，还需要同步 `uploads_data` 中的文件。

如果资源都已经在 R2 或七牛，对数据库迁移通常就够了。

## 十二、最简命令版

### 本地

```bash
docker compose exec -T postgres pg_dump -U sym -d sym -Fc > init-data.dump
scp init-data.dump <server_user>@<server_ip>:/tmp/init-data.dump
```

### 服务器

```bash
docker compose --env-file .env.docker stop api worker beat
docker compose --env-file .env.docker exec -T postgres psql -U sym -d sym -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
cat /tmp/init-data.dump | docker compose --env-file .env.docker exec -T postgres pg_restore -U sym -d sym --no-owner --no-privileges
docker compose --env-file .env.docker up -d
```
